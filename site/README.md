# STAKEOUT: сайт блога

Статический многостраничный сайт без сервера, базы данных и админки: HTML, CSS и JS без зависимостей.
Нечему «ломаться» на сервере: нет PHP, CMS, форм входа и SQL.

```
site/
  index.html            стартовый экран: заставка с логотипом, меню разделов, фон «дым»
  stories.html          Рассказы
  gear.html             Снаряжение
  units.html            Подразделения
  guides.html           Гайды
  404.html              страница «не найдено» (адреса от корня сайта)
  assets/css/core.css   общее: токены, шапка, фон, плашки разделов, подвал, переходы
  assets/css/home.css   только стартовый экран: заставка, герой, карточки
  assets/js/boot.js     в <head>, до первой отрисовки: часы сессии, флаг заставки
  assets/js/core.js     общее: часы DTG, фон «дым» (WebGL)
  assets/js/home.js     только стартовый экран: заставка, полутоновые карточки
  assets/img/logo.svg   логотип (шапка и иконка вкладки)
  _headers              заголовки безопасности (Cloudflare Pages / Netlify)
```

## Как устроены переходы

- Контент каждой страницы лежит в её HTML. Скрипты ничего не подгружают и не собирают из строк.
- Между страницами работает межстраничный View Transitions API (только CSS, `@view-transition`):
  шапка показывается «вживую» весь переход, полоса активного раздела переезжает к новому пункту,
  карточка раздела на главной превращается в плашку на странице раздела.
- Анимации шапки (линия сканирования, индикатор записи) и фон «дым» идут по общим часам сессии
  (`boot.js`, `sessionStorage`), поэтому после перехода продолжаются с той же фазы, а не с начала.
- Заставка показывается один раз за сессию вкладки.
- Браузеры без межстраничных переходов (сейчас Firefox) получают обычную загрузку страницы
  с коротким появлением контента. При `prefers-reduced-motion` анимации отключены.

Шапка и подвал одинаковые на всех страницах. При правке меняйте их во всех шести файлах
одинаково, иначе шапка будет «мигать» при переходе.

## Локальный просмотр (Windows 10)

```powershell
py -m http.server 8080 --directory site
# открыть http://localhost:8080
```

Заголовки из `_headers` применяются только на хостинге. 404-страница локально
не подставляется.

## Деплой

Cloudflare Pages: Create project → Connect to Git → этот репозиторий,
Build command пусто, Build output directory `site`. Файл `_headers` подхватывается сам.
`404.html` в корне отключает режим SPA: несуществующие адреса получают код 404.

## Защита

Уже в коде:

- CSP без `'unsafe-inline'` и `'unsafe-eval'`, Trusted Types включены без единой политики:
  на страницах нет встроенных скриптов, стилей и обработчиков; текст пишется только через `textContent`.
- Данные из `sessionStorage` проверяются как недоверенные (тип и диапазон чисел).
- Запрет встраивания во фрейм (`frame-ancestors 'none'`, `X-Frame-Options`).
- HSTS, `nosniff`, строгий `Referrer-Policy`, отключённые API браузера.
- Ни одной сторонней JS-библиотеки: нет цепочки поставок, которую можно подменить.

Сделать на аккаунтах (основной риск для статического сайта: угон аккаунта, а не взлом кода):

1. 2FA с ключом или приложением на GitHub, хостинге, регистраторе домена и почте.
2. Защита ветки `main` на GitHub: изменения только через pull request.
3. DNSSEC и CAA-запись (`0 issue "letsencrypt.org"` или ваш CA) у регистратора.
4. Cloudflare: Always Use HTTPS, TLS 1.2+, Bot Fight Mode, правило rate limiting.
5. Шрифты перенести в `assets/fonts` и убрать Google Fonts из CSP
   (`style-src 'self'; font-src 'self'`): ноль внешних запросов.
6. Проверить заголовки после деплоя: https://securityheaders.com и https://observatory.mozilla.org.
